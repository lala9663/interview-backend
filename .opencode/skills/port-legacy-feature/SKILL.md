# 기존 기능 옮기기

기존 코드는 한 서비스 안에 화면 로직, 업무 규칙, DB, 프롬프트, 모델 호출이 섞여 있는 경우가 많다.
**그대로 번역하지 않는다.** 기능을 쪼개서 세 레포 가운데 맞는 곳으로 보낸다.

| 레포 | 가져가는 것 |
| --- | --- |
| `interview-backend` (여기) | 저장(DB), 권한, 업무 규칙(상태 전이·검증), 작업 관리, 다른 시스템과의 데이터 교환 |
| `interview-agent` | 프롬프트, 모델 호출, STT, 임베딩·유사도, 텍스트 분석, 실시간 처리 |
| `interview-frontend` | 화면, 입력 검증의 사용자 안내, 표시용 가공 |

## 1. 기존 기능을 읽고 분해한다

기존 코드에서 그 기능의 진입점(라우트, 화면의 버튼)부터 끝까지 따라가며 아래 표를 채운다. **코드를 쓰기 전에 표부터 만든다.**

| 계층 | 기존 코드에서 찾을 것 | 갈 곳 |
| --- | --- | --- |
| 화면 | 컴포넌트, 화면 상태, 표시 문구 | frontend |
| API | 경로, 요청·응답 모양 | API 명세(`docs/contract/api-contract.md`)에 맞춘다 |
| 권한 | 누가 할 수 있는가(역할, 소유자 검사) | **backend** |
| 업무 규칙 | 상태 전이, 검증, 중복 처리, 계산 규칙 | **backend** |
| 저장 | 테이블·모델, 조회 조건, 트랜잭션 범위 | **backend** |
| AI | 프롬프트, 모델 호출, 후처리(파싱·필터), 유사도 | agent |
| 비동기 | 큐, 백그라운드 작업, 재시도, 제한 시간 | 작업 관리는 **backend**(AiJob), 실행 내용은 agent |
| 외부 연동 | 다른 사내 시스템 호출, 파일 입출력 | 데이터 교환이면 **backend**, 모델·음성이면 agent |
| 설정 | 환경변수, 하드코딩된 값 | 각 레포의 설정 |

## 2. 어디로 보낼지 헷갈릴 때의 판단 기준

위에서부터 차례로 묻는다.

1. **DB 에 쓰는가?** → backend. Agent 는 DB 에 닿지 않는다. Agent 가 만든 결과를 저장해야 하면 Agent → backend 내부 API(API 명세 5장)로 보낸다.
2. **모델(LLM, STT, 임베딩)을 부르거나 프롬프트를 다루는가?** → agent. 여기에 프롬프트 문자열이나 모델 주소를 두지 않는다.
3. **"누가 할 수 있는가"를 정하는가?** → backend. 화면에서 버튼을 숨기는 것만으로 끝내지 않는다.
4. **상태가 바뀌는가(면접 상태, 방 상태, 제출 여부)?** → backend 가 바꾼다. Agent 나 프론트가 상태값을 직접 정해 보내지 않는다.
5. **글을 분석·판정하는가(키워드 추출, 유사도, 금지 표현 검출, 요약)?** → agent. 규칙 기반(정규식)이라도 "글의 뜻"을 다루면 agent 다.
6. **정해진 규칙의 계산인가(합계, 평균, 건수, 정렬)?** → backend.
7. **블라인드 처리인가?** → 두 곳이다. **구조화된 항목**(성별·생년월일 같은 컬럼)을 버리는 것은 backend(`excel-mapping.yml`), **글 속의 표현**을 거르는 것은 agent.
8. **오래 걸리는가(수 초 이상)?** → backend 가 `AiJob` 으로 접수하고 상태를 보여 준다. 요청 스레드에서 기다리지 않는다.
9. **표시만 다른가(날짜 형식, 문구, 색)?** → frontend. 백엔드는 원래 값(코드, ISO 시각)을 준다.

기존 코드의 한 함수가 여러 곳에 걸쳐 있으면 **함수를 쪼갠다.** 예: "면접 종료" 함수가 상태 변경 + 프롬프트 호출 + 저장을 한다면
→ backend: 상태 변경, 작업 접수, 결과 저장 / agent: 프롬프트 호출.

## 3. 이 레포 몫을 옮긴다

1. **범위 확인.** 이 서비스의 범위는 면접 전(업로드·매칭·브리핑), 면접 중(방·전사·메모), 면접 후(평가·보고서)다.
   서류 선별, 일정 조율, 합격 통보 같은 것은 범위 밖이다. 범위 밖이면 옮기지 말고 사람에게 묻는다.
2. **API 명세 확인.** 그 기능의 API 가 API 명세에 있는가? 없거나 모양이 다르면 `change-api-contract`. 기존 API 의 경로·필드명을 그대로 가져오지 않는다(API 명세가 기준이다).
3. **이미 있는지 확인.** 같은 개념이 이 레포에 있으면 새로 만들지 않는다.
   - 기존의 "지원자" = `candidate.Candidate`, "면접 세션" = `interview.Interview` + `room.Room`, "스크립트/대화록" = `room.Utterance`
   - 기존의 "요약/사전 분석" = `briefing.Briefing`, "평가표" = `evaluation.*`, "결과 리포트" = `report.Report`, "백그라운드 작업" = `job.AiJob`
4. **데이터 모델.** 기존 테이블을 그대로 복사하지 않는다. `add-entity-and-migration` 의 규칙(IV_ 접두사, 시퀀스 PK, 예약어, 연관 매핑 없음)에 맞춰 다시 만든다.
   기존 모델에 블라인드 항목(성별, 나이, 가족, 주소, 사진)이 있으면 **가져오지 않는다.**
5. **업무 규칙.** 기존 코드의 규칙을 문장으로 먼저 적고(주석이나 PR 설명), 그 문장대로 서비스에 구현한다.
   Python 의 동적 처리(딕셔너리 그대로 넘기기, None 허용)는 DTO 와 명시적 검증으로 바꾼다.
6. **AI 호출 지점.** 기존 코드가 모델을 부르던 자리는 `AgentClient` 호출로 바꾼다.
   - API 명세 4장에 맞는 호출이 있으면 그것을 쓴다.
   - 없으면 agent 레포에 새 내부 API 가 필요하다 → `change-api-contract` → `AgentClient` 에 메서드 추가 → `HttpAgentClient`, `FakeAgentClient`, `AgentDtos` 를 함께 고친다.
   - Agent 구현이 아직 없어도 `FakeAgentClient` 로 이 레포의 작업은 끝낼 수 있다.
7. **Java 8 로 쓴다.** Python 코드를 줄 단위로 번역하지 않는다. 컴프리헨션은 for 문으로, f-string 은 문자열 연결로, dataclass 는 Lombok DTO 로.
   `var`, `record`, `List.of`, text block 은 쓸 수 없다.
8. **기능 플래그.** 한 번에 못 끝내면 `app.features.<이름>: false` 뒤에 두고 작은 PR 로 나눠 합친다.
9. 나머지는 `add-api-endpoint` 의 순서(DTO → service → controller → 권한 → 테스트)를 따른다.

## 4. 가져오면 안 되는 것

- 프롬프트 문자열, 모델 이름·주소, 토큰 수 계산, 모델 응답 파싱
- 음성 파일 처리, STT 호출, 화자 분리
- 임베딩·유사도 계산, 키워드 추출, 금지 표현 검출
- 화면 문구, 날짜·숫자 표시 형식, 정렬·필터의 화면 상태
- 기존 코드의 네이티브 SQL, DB 종류에 묶인 함수(JSON 함수, `LIMIT`, 자동 증가 키)
- 실제 사람의 데이터, 사내 주소, 비밀키(테스트 데이터·주석·예시에도 넣지 않는다)
- 기존 코드의 블라인드 항목 컬럼

## 5. 다른 레포에 넘길 것을 적는다

이 레포에서는 다른 레포의 코드를 고칠 수 없다. 넘길 내용을 PR 설명(또는 작업 보고)에 적는다.

```
[agent 레포에 필요한 것]
- 기존 위치: legacy/services/summary.py 의 build_prompt(), call_llm()
- 하는 일: 이력서 요약을 만들고 금지 표현을 거른다
- 필요한 내부 API: POST /internal/v1/… (요청·응답 모양)   ← API 변경 필요 여부

[frontend 레포에 필요한 것]
- 기존 위치: legacy/web/src/views/Result.vue
- 하는 일: 버전을 고르는 화면
- 쓰는 API: GET /api/v1/interviews/{id}/report/versions
```

## 6. 체크리스트

- [ ] 분해 표(1장)를 만들었고, 계층마다 갈 곳을 정했다
- [ ] 이 서비스의 범위 안인지 확인했다
- [ ] 이 레포에는 저장·권한·업무 규칙만 들어왔다(프롬프트·모델 호출·텍스트 분석 없음)
- [ ] API 명세의 경로·필드명을 따랐다(기존 API 의 이름을 가져오지 않았다)
- [ ] 이미 있는 엔티티·서비스를 다시 만들지 않았다
- [ ] 블라인드 항목을 가져오지 않았다. `BlindFieldTest` 통과
- [ ] 엔티티는 Oracle 규칙을 지켰고 `./gradlew generateOracleSchema` 를 돌렸다
- [ ] AI 호출은 `AgentClient` 를 거친다. `FakeAgentClient` 로 테스트가 돈다
- [ ] 권한(ADMIN / 배정된 면접관)을 서버에서 검사한다
- [ ] agent·frontend 레포에 넘길 것을 적었다
- [ ] `./gradlew build` 통과, 문서(`docs/`) 갱신
